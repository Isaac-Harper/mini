# Build, signing, release and codecs

Detail for bundling, signing, the release script and the proprietary-codecs CEF. AGENTS.md has the one-line summaries.

## Build and bundle

- `scripts/bundle.sh`, `Makefile`: build Rust + Swift, assemble and sign `build/Mini.app`. Helper plists are generated by the script.
- Env: `CONFIG` (release|debug), `CEF_PATH` (default from `scripts/cef-path.sh`; a directory with `archive.json` at its top is used as the CEF directory itself, anything else as the parent of `<version>/cef_macos_aarch64`), `MINI_CEF_CODECS=0` (stock CEF even when the codecs build is installed), `MINI_SIGN_IDENTITY` (default: first Developer ID Application or Apple Development identity, else `-` ad-hoc with a warning), `SKIP_SHELL=1` (bundle without the Swift binary; the app itself is then left unsigned).
- `make install` quits a running Mini (`osascript ... to quit`), waits up to 30 s for every Mini process to exit, replaces `/Applications/Mini.app` with ditto, runs lsregister and relaunches it in the background with `open -g`.
- `scripts/cef-path.sh`: prints the `CEF_PATH` for local builds: `~/.local/share/cef/<version>-codecs/cef_macos_aarch64` when it holds `archive.json` and `MINI_CEF_CODECS` is not `0`, else `~/.local/share/cef`. The Makefile passes `MINI_CEF_CODECS` to it explicitly because make 3.81's `$(shell)` does not see command-line variables.

## Bundle resources

- `bundle/AppIcon-1024.png`, `bundle/AppIcon.icns`: the app icon (masked 1024 PNG source; the committed icns holds 16 through 512@2x, generated once with `sips -z` into an `.iconset` and `iconutil -c icns`, not at build time). `bundle.sh` copies the icns into `Contents/Resources` before signing; the helpers have no icon. JS alert panels show it.
- `bundle/Info.plist`: main app plist template (`CFBundleIconFile` `AppIcon`, `NSPrincipalClass` `Mini.MiniApplication`, http/https URL types, location usage strings for the weather row, `CFBundleShortVersionString` checked by the release script).
- `bundle/Mini.entitlements` (main app: `device.audio-input`, `device.camera`, `personal-information.location`, the hardened-runtime resource entitlements for web camera/mic and the weather row), `bundle/MiniHelper.entitlements` (GPU, Renderer and Plugin helpers: `cs.allow-jit`, `cs.allow-unsigned-executable-memory`, `cs.disable-library-validation`; the plain and Alerts helpers get none).

## Signing

- Ad-hoc signing traps cookie encryption: Chromium reads the "Chromium Safe Storage" login-keychain item at startup, and its ACL trusts each ad-hoc build by cdhash. Any code change gives a new cdhash, so the next launch raises a SecurityAgent "Always Allow" prompt; until it is answered the cookie store never loads and every navigation stalls before reaching the network (blank page, stop button, no load_start). bundle.sh therefore signs with a stable certificate identity by default, whose keychain grant survives rebuilds. With ad-hoc signing, answer the prompt. Identical sources rebuild to the same cdhash.
- `--use-mock-keychain` confirms that diagnosis but re-encrypts cookies with a fixed key, so never run it against the real profile (test instances use it only with a scratch profile; see testing-harness.md).
- Every build signed with a certificate uses the hardened runtime (`--options runtime`) so local and released builds behave the same; ad-hoc builds skip it because library validation would reject the separately signed framework without a Team ID. Local builds sign with `--timestamp=none` (no network round trip per binary); `MINI_TIMESTAMP=1` adds the secure timestamp notarization needs.
- The hardened runtime does not change the designated requirement (identifier + Developer ID leaf, OU 5W853CJW28), so the Chromium Safe Storage keychain grant survives. Verified under the hardened runtime: pages load, VP9 video plays (GPU process), the camera permission card appears, weather re-fetches location.

## Release

- `scripts/release.sh <version>` / `make release VERSION=X.Y.Z`: refuses a dirty tree, an unpushed HEAD, an existing tag or a version that differs from `bundle/Info.plist`; builds with the stock CEF (`MINI_CEF_CODECS=0`, `CEF_PATH=~/.local/share/cef`), the Developer ID identity and `MINI_TIMESTAMP=1`, runs `scripts/check-stock-cef.sh` on the bundle, zips with `ditto -c -k --keepParent`, `notarytool submit --wait` (keychain profile `lowlight-notary`, override with `MINI_NOTARY_PROFILE`), staples, checks `spctl`, re-zips `dist/Mini-<version>-arm64.zip` and runs `gh release create`.
- `scripts/check-stock-cef.sh <app>`: release guard; fails if the bundled framework has the marker file or the string `Creating H264DecoderImpl.` (WebRTC's ffmpeg H.264 decoder, only compiled with the proprietary codecs). Codec descriptor names such as "H.264 / AVC" are in the stock binary too, and official builds compile ffmpeg's `av_log` messages out, so neither can tell the builds apart.
- Released builds never carry the proprietary codecs; the stock CEF has none, so H.264 MP4 plays only with the local codecs build (unrelated to signing).

## Proprietary codecs CEF

- `scripts/build-cef-codecs.sh`: builds CEF with proprietary codecs from source in `~/code/cef-build` (override `CEF_BUILD_DIRECTORY`) and installs it to `~/.local/share/cef/156.0.14-codecs/cef_macos_aarch64` in the stock layout, plus `archive.json` and the marker `Chromium Embedded Framework.framework/Resources/proprietary_codecs.txt`; then deletes `out/`, and the Chromium checkout too when under 40 GB would be free.
- Built 2026-10-29 on an M5 with Xcode 27.1, macOS 26.6: CEF commit 4fa4ab5 on branch 8078 (Chromium 156.0.8078.48), the exact build the crate wraps; headers match the stock distribution apart from comments, so the same `libcef_dll_wrapper` and API hash work.
- GN_DEFINES `is_official_build=true proprietary_codecs=true ffmpeg_branding=Chrome symbol_level=0 chrome_pgo_phase=0`; `automate-git.py --branch=8078 --checkout=<commit> --arm64-build --no-debug-build --no-chromium-history --minimal-distrib --no-distrib-docs --no-distrib-symbols --no-distrib-archive --build-target=cefclient`.
- It took 3 h 11 min (sync about 18 min, the rest compile and link) and peaked at about 52 GB of disk (checkout 32 GB, `out/` 11 GB); after `out/` is removed the checkout stays at 32 GB in `~/code/cef-build`. Installed size 349 MB.
- Verified in a scratch instance: an H.264 + AAC MP4 plays (`canPlayType` "probably", frames 3 s apart differ), `decodeAudioData` decodes an AAC m4a; the stock framework fails the same page with `DEMUXER_ERROR_NO_SUPPORTED_STREAMS`.
