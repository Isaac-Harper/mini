# Swift shell and UI

Detail for the Swift shell: coordinator, keys and menus, window and page card, sidebar, overlays and page features. Tabs, undo and little windows are in tabs-and-undo.md; spaces and history in spaces-and-session.md. AGENTS.md has the one-line summaries.

## Coordinator

- `AppDelegate.swift`: builds the shell, menu and window at launch; dock reopen; URLs from other apps (queued until launch) go to `openExternalURL`, which opens a little window.
- `ShellController.swift`: central coordinator: launch, tab store observer, browser lifecycle, focus model.
- Page focus across navigations: a navigation swaps Chromium's `RenderWidgetHostViewCocoa` inside `WebContentsViewCocoa` (cross-site and same-site alike; the old view is hidden, not removed, which drops first responder to the window), so the page lost keyboard focus after every pill, command bar or link navigation. `navigate` on the selected tab, and a load that starts while first responder is inside the selected tab's host view, set `Tab.refocusesOnCommit`; `addressChanged` (the commit, by which the new view is in place) clears it and focuses the page again if first responder is then the window or nil. A new tab's first focus still comes from `needsInitialFocus` once its browser view is attached.
- `BrowserEvents.swift`: ShellController extension handling every engine callback.
- `BrowserHostView.swift`: NSView that CEF embeds the windowed (non-OSR) browser view into as a subview; sizes subviews to bounds. Switching tabs swaps which host view is visible and calls `mini_browser_set_hidden`.

## Keys and menus

- App shortcuts beat the page: `pre_key_event` hands Cmd/Ctrl key-downs to Swift, which runs matching browser-command menu items and consumes them. Edit-menu shortcuts (copy, paste, select all) are never consumed there.
- Cmd-Z / Shift-Cmd-Z are the one split case: `pre_key_event` consumes them for tab undo only when the main window is key, no overlay is active, the tab is displayed and `mini_browser_has_editable_focus` is false; unknown editable state counts as editable, so a page gets Cmd-Z unless it reported a plain focus.
- Outside the page the Edit menu's Undo/Redo items (tags 7801/7802) are retargeted in `menuNeedsUpdate` (`updateUndoMenuItems`): to `undoTabAction:`/`redoTabAction:` with the undo manager's titles ("Undo Close Tab") when `undoRoutesToTabs`, else back to nil-target `undo:`/`redo:` so field editors (command bar, find bar, prompts) and editable pages keep their own undo.
- `ShellCommands.swift`: menu actions and validation (extension of ShellController).
- `MenuKeyEquivalents.swift`: matches `pre_key_event` NSEvents to main-menu items, excluding standard edit actions and the tab undo actions; `undoDirection` spots Cmd-Z / Shift-Cmd-Z, which `BrowserEngine` hands to `pageUndoKeyPressed` instead.
- `MainMenu.swift`: the main menu, built in code.
- Hidden menu items need `allowsKeyEquivalentWhenHidden = true` to keep their shortcut (used for Cmd-+ and Opt-Cmd-Up/Down).
- Menu icons and order (macOS 26 style): every main menu item and every context menu item (tab row, split row, pinned tile, multi-selection, page, link, image, selection, space button) carries an SF Symbol (`MainMenu.item(..., symbol:)` and `MainMenu.symbolImage`, which fails loudly on a missing name; SwiftUI menus use `Button(_:systemImage:)` and a `Label` for the Space Color picker), except destructive items, which stay plain text: Close, Delete, Archive, Clear, Reset. Context menus group in one order with a separator between groups: Open (Open in Split View, Duplicate, Open Link/Image in New Tab), then Edit and Copy (Cut, Copy, Paste, Copy Link, Look Up, Search, Rename), then Organize (Pin, Save, Remove from Saved, Separate, Space Color, Save Image), then the destructive items last. The page menu's Back/Forward/Reload and Inspect Element keep their own trailing sections; spelling suggestions stay plain. The main menu keeps the standard macOS menu order with each destructive item at the end of its menu or group.

## Window and page card

- `MainWindowController.swift`: window built on NSSplitViewController (native floating glass sidebar item, autosaved as `MainSplitView`), web content item with `automaticallyAdjustsSafeAreaInsets`. Sidebar collapse is noticed through `NSSplitView.didResizeSubviewsNotification`. The page card lives in the content split item, so collapsing or expanding (toggle, divider snap, keyboard) moves it in lockstep with the sidebar on the split view's own animation, and CEF's view is resized on every animation frame; frame captures at 30fps of a toggle collapse and expand show no stretched, stale or black frames, so no snapshot swap is used.
- The page is a card: `PageCardView` (layer shadow, no clipping) inset 8pt from the window edges and the sidebar (`safeAreaLayoutGuide` leading), holding `webAreaView`, whose layer clips with an 18pt continuous corner radius, concentric with the window's 26pt corners (`CornerMetrics.concentric`: outer radius minus inset, so both curves share a center); `setPageFillsWindow` drops the inset, radius and shadow for page fullscreen.
- An `EmptyPageView` (layer-backed, centered on the card above `webAreaView`: "Mini" and "⌘T to open a page" in secondary label colors) shows whenever `display` gets no host views; closing the last tab does not change selection (`select(nil)` is a no-op when nothing is selected), so `tabStore(didRemove:)` refreshes the displayed tabs itself once none are left.
- `WebAreaView` sizes every host view to its bounds on each layout, or, with a `splitArrangement`, places the two split host views either side of a 6pt `SplitDividerView` (min 320pt per side, dragged with a `trackEvents` loop, accepts first mouse) and puts the hit-test-transparent `SplitFocusBorderView` (2pt accent at 70%) over the focused side.
- `WebAreaView` also owns the 2pt accent `LoadingProgressLineView` along the card top (clipped by the card corners): `showLoadingProgress(of:)` runs from `loading_progress_changed`, `loading_state_changed` and `refreshDisplayedTabs` for the selected tab, animates width to the real progress, and on finish eases to full width over 0.2s, holds a soft accent glow (layer shadow, radius 3) for 0.15s (`glowHold`), then fades out over 0.25s; any new progress or an unanimated finish drops the glow. It only moves with real `loading_progress_changed` values, never a timer. A tab switch sets it without animation.
- `GlassTooltip.swift`: the one tooltip. `GlassTooltip.shared` shows a borderless, mouse-transparent child panel holding an `NSGlassEffectView` (the 8pt row corner radius, 11pt caption text, one line with middle truncation, at most 420pt wide) 4pt below the anchor, kept 8pt inside the window horizontally and flipped above when it would leave the screen. Timing as on macOS: 0.6s after the pointer enters, then instantly while the pointer moves to a neighbor within 0.5s of the last tooltip hiding; a click, key or scroll hides it until the pointer leaves that control. SwiftUI uses `.glassTooltip(_:)` (a background `TooltipAnchorView` with its own tracking area, so it works over AppKit representables such as the AirPlay buttons, plus the text as accessibility hint), AppKit uses `HoverHighlightButton.tooltip` (toolbar and collapsed-cluster buttons; also set as accessibility help). `fadingTruncation(tooltip:)` offers the full title only while it overflows (tab rows and split halves); address pill chips carry theirs. No `.help()` or view `toolTip` is left; only native menu items (history menus) and the little window's standard toolbar items keep AppKit tooltips.
- `FocusRing.swift`: the one keyboard focus ring, in the space accent: `FocusRingMetrics` (2pt at 85% opacity, 3pt solid with Increase Contrast, drawn 3pt outside the control with a concentric radius, control radius plus the offset). SwiftUI `FocusRing` (sidebar keyboard focus, the address pill while editing as a capsule), AppKit `FocusRingLayer` and `FocusRingView` (the command bar field row, concentric with the panel; `HoverHighlightButton` shows it when it becomes first responder through Full Keyboard Access, colored by `focusAccent`, which the toolbar and cluster set to the current space color).
- `HoverHighlight.swift`: the one hover style. SwiftUI `.hoverHighlight(cornerRadius:suppressed:isHovered:)` (a quaternary fill, tertiary with Increase Contrast, in the same concentric radius as the control, fading in over 80 ms and out over 150 ms, suppressed under a selection; `isHovered` hands the state to rows for their close buttons) is on tab rows, split rows, pinned tiles, footer rows (Now Playing, weather, downloads, New Tab) and space buttons; `HoverHighlightButton` is the AppKit twin (tracking area, a layer fill animated with the same timings) used by the toolbar and collapsed-cluster buttons, so both sets look the same. The little window keeps its native unified toolbar items.
- Symbol effects (all skipped or crossfaded with Reduce Motion, nothing loops): `HoverHighlightButton` hosts its symbol in an `NSImageView` that never hit-tests (`showSymbol`; NSButton has no symbol-effect API, and an image view that takes the mouse-down swallows the click) so a mouse click bounces it (`addSymbolEffect(.bounce)`: back, forward and the sidebar toggle; menu and keyboard triggers do not bounce); play/pause and the pill's reload/stop swap with `.contentTransition(.symbolEffect(.replace))`; a space button bounces when it becomes the current space.
- `WindowToolbar.swift`: NSToolbar whose only items (sidebar toggle, back, forward) sit before `.sidebarTrackingSeparator`, so they render inside the sidebar next to the traffic lights; the toolbar draws no band of its own because the page card runs up under the transparent titlebar. All three are borderless view items (32x28 `HoverHighlightButton`s styled by `WindowToolbar.style`, 15pt symbols, matching the collapsed cluster); back and forward are `HistoryToolbarItem`s with a `HistoryButton`, validated through its `validation` closure since view items skip `validateToolbarItem`). While the sidebar is collapsed the items are hidden (`NSToolbarItem.isHidden`).
- `WindowControlsCluster.swift`: the collapsed-sidebar controls. While collapsed the real traffic lights are hidden; a hit-test-transparent `HoverZoneView` (268x56 at the top-left, tracking area) reveals them plus a 244x36 `NSGlassEffectView` capsule behind them holding the sidebar toggle and back/forward `HistoryButton`s at the same x positions as the toolbar items, and hides both 1s after the pointer leaves.
- `PeekSidebarController.swift`: peek sidebar while collapsed. A 6pt `HoverZoneView` on the window's left edge slides a second `SidebarView` (own `SidebarHostingView` in an `NSGlassEffectView`, concentric radius 18, same 8pt inset and width as the last expanded sidebar) in over the page in 0.2s (fade with Reduce Motion) without resizing the page, and shows the cluster's controls without their capsule over its top row. It hides 0.3s after the pointer leaves the panel (`PeekPanelView` tracking area), deferred while a mouse button is down or a sidebar drag is active, and never starts during either. The toggle expands the real sidebar, which disables and hides the peek.

### AppKit facts for the window

- The sidebar NSHostingView must have `sizingOptions = []`, or SwiftUI's fitting size fights the split view and the sidebar renders offset and clipped.
- The page card runs to 8pt from the window top, under the transparent unified titlebar and toolbar. Clicks there still reach the page: the theme frame hit-tests into `RenderWidgetHostViewCocoa` (verified with a page reporting `mousedown` at clientY 6). The empty strip above the card is a plain container view, so it drags the window. The traffic lights keep their native position (toolbar-height titlebar, centred 26pt from the top); they are hidden and shown, never moved.
- NSBackgroundExtensionView is not used: it mirrored the page under the sidebar, which makes no sense for an inset card, and its internal hosting view swallowed clicks.
- An NSHostingView whose content can be empty (command bar suggestions) must drop `.maxSize` from `sizingOptions`, or its required max-width constraint collapses fixed-width containers.
- Overlays live in the content item's view (`rootView`), never in the NSSplitView itself (its subviews are panes).
- A plain (non-layer-backed) view added as a sibling above the layer-backed `webAreaView` draws underneath it, invisible; overlays on the card must set `wantsLayer` (verified with the empty page view).
- In an inactive window AppKit delivers the activating click only to views whose `acceptsFirstMouse` returns true (CEF's browser views do); the split divider overrides it so it drags on the first click.
- A `CATransition` added to `webAreaView`'s layer leaves CEF browser views blank when they are unhidden in the same transaction (tab switch back to an existing browser showed an empty web area). Animate `alphaValue` instead.

## Sidebar

- `SidebarView.swift`, `TabRowView.swift`, `PinnedTabsView.swift`: SwiftUI sidebar content. `SpaceTabsView` is one space's pinned tiles and tab list; it sets the `sidebarStore` environment value, which rows and tiles read for selection so a neighbor space can render during a swipe.
- The tab list fades over 16pt under the pinned tiles and above the footer only when content is scrolled past that edge: `onScrollGeometryChange` derives `ScrollEdges` (content above the top, content below the bottom) and `ScrollEdgeFade` masks the `ScrollView` with a gradient per edge, animated 0.15s. The native `scrollEdgeEffectStyle` compiles on macOS 26 but whether it draws without a bar overlapping the scroll view could not be checked, so the mask is used.
- Tab rows keyed by tab id slide in from the leading edge with a fade; a closed row collapses (`RowCollapse`, a vertical scale anchored at its top) and fades while the rest of the list springs up into its place and the selection highlight glides to the newly selected row, and rows closed together collapse together (`.spring(duration: 0.2)` on the list, keyed by `visibleTabs` ids; Reduce Motion: fade only, 0.15s ease).
- Launch reveal (`LaunchReveal.swift`, `ShellController.launchReveal`): when the window first appears the page card starts at alpha 0 and fades in over 0.35s, and the pinned tiles and tab rows fade in while rising 4pt (0.3s ease-out each, staggered 20ms per row; rows past the 12th start together). It runs once per launch from `launch`, so later rows, space switches and sidebar expands never replay it; with Reduce Motion it starts done and nothing animates.
- The selected row's highlight and the selected pinned tile's tint glide between rows and tiles (`matchedGeometryEffect` in a `SpaceTabsView` namespace passed through the `selectionNamespace` environment value, spring 0.28s keyed by the selected tab id; Reduce Motion drops the namespace so it fades in place). The command bar's keyboard highlight glides the same way (keyed by `selectedIndex`; typing updates run with animations disabled, so only arrows and hover glide). `RowHighlight` draws the strong selection, the softer multi-select tint (accent 12%) and hover.
- Space buttons row at the bottom with a context menu and a New Space button.
- `FadingTruncation.swift`: long titles fade out over 16pt (`SidebarMetrics.titleFadeWidth`) at the trailing edge instead of ending in an ellipsis: `fadingTruncation()` lays out a hidden one-line copy (so the title never widens the row), overlays the full-width text and masks it with a gradient only when it overflows, so a hover close button narrowing the row moves the fade with it. Used by tab rows, split halves and the address pill. `FadingTextField` does the same in AppKit with a `CAGradientLayer` mask (and leading alignment while it overflows) for the little window's host field, dropped while editing.
- Glass address pill with reload/stop: the registrable domain (`AddressEmphasis` in `Sources/MiniRules`, unit tested, splits around whatever its injected resolver returns; the app passes `URLInput.registrableDomain`, which asks the core's public suffix list through `mini_registrable_domain_length`, so foo.github.io and bbc.co.uk stay whole and IP addresses, public suffixes and single labels are emphasized whole) shows in the primary label color and the subdomain, scheme and path in secondary. Clicking a page's address morphs the pill into an inline `TextField` in the same frame (0.15s crossfade, the full URL selected by the field becoming first responder); Return navigates through `open(_:from: .editCurrent)`, Escape (`onKeyPress`, since `onExitCommand` never fired there) or losing focus or a tab switch morphs back, and both Return and Escape hand first responder to the page before the field goes away (otherwise the orphaned field editor kept it). With no page the click still opens the command bar; Cmd-L still opens the command bar. Hovering swaps the host for the full URL, fading at the end, with the full URL as tooltip; `URLInput.isInsecure` pages (http: except localhost, `*.localhost`, 127.0.0.1 and ::1) get a leading `lock.slash` glyph with a "Not Secure" tooltip.
- `AddressPillBadges.swift`: small caption chips after the address (hidden while editing), each an `AddressPillChip` (tertiary fill capsule, 16pt, hugging its text, which is tail truncated at 92pt). Preview deployments (`PreviewDeployment` in `Sources/MiniRules`, unit tested: Vercel `<project>-git-<branch>-<scope>.vercel.app`, the scope being the last dash segment or the last two when it ends in `-projects`, and `<project>-<9 char hash>-<scope>.vercel.app`; Netlify `deploy-preview-N--site`, `<24 hex>--site` and `<branch>--site` on netlify.app; Cloudflare Pages `<8 hex or branch>.<project>.pages.dev`) get "Preview" plus the branch when the host has one.
- Vitals peek (`VitalsPeek.swift`): `page_vitals_changed` sets the observable `Tab.vitals` (`WebVitals` in `Sources/MiniRules`, unit tested: Google's thresholds LCP 2.5/4s, INP 200/500ms, CLS 0.1/0.25, TTFB 0.8/1.8s, good inclusive of its limit; values as "142ms", "1.4s", "0.03", "…" when not measured), reset when the tab starts loading. Hovering the address pill for 0.5s opens `VitalsPopoverPresenter`'s `NSPopover` beside it (http(s) pages with a browser; closes 0.15s after the pointer leaves both, on editing and on a tab switch): the four values in a 2x2 grid, each with a green, orange or red dot, observed live so INP updates while it is open. A faint orange 5pt dot joins the pill's chips only while LCP or CLS is poor. Background test instances never fire SwiftUI hover, so the harness calls `pillHoverChanged` with the pill's `PillAnchorView`; a synthesized click sent straight to `RenderWidgetHostViewCocoa` produces a real event timing entry (INP 304ms for a 300ms handler).
- Preload on Hover (`HoverPreloader.swift`, View > Preload on Hover, UserDefaults `PreloadsOnHover`, on by default): when the selected main-window tab's hovered link (`status_message_changed`) stays the same for 150ms, `mini_browser_preload` adds one speculation rules prefetch for it, replacing the previous one; an empty status (pointer left the link) removes it. Only http(s) links on the page's scheme and registrable domain, never the same document, never action-like URLs (`HoverPreload` in `Sources/MiniRules`, unit tested: logout, signout, delete, unsubscribe, remove, destroy in the path or query, or an `action`, `do` or `method` parameter), and never in Low Power Mode or on an expensive or constrained network (`NWPathMonitor`). The command bar does not warm results: a browser-initiated `load_url` does not use the document's prefetch (measured: 330ms first paint either way).
- Experiment behind it (5 runs each, click to first paint median; local page with 300ms TTFB and a heavy body): none 333ms, preconnect 337ms, prefetch 37ms, prerender 45ms; nextjs.org to /docs 114, 105, 53, 40ms; github.com to /features 141, 133, 121, 129ms; vercel.com already prefetches /docs with its own rules (77ms with nothing added). Prerender never activated in CEF 156 Alloy (`activationStart` 0, `deliveryType` navigational-prefetch), so prefetch is the kept option; a hidden offscreen browser swap was not built.
- Reload time (`ReloadTiming.swift`): a user reload (the pill's reload button, Cmd-R and the `>` Reload Page action through `reloadPage(_:)`, the page menu's Reload) goes through `reloadByUser`, which sets `Tab.awaitsReloadTiming`; the next `page_vitals_changed` with a load time shows it beside the reload button ("142ms", "1.4s", `DurationText`) in the caption font and secondary color, fading in and out over 0.2s (instant with Reduce Motion) and held 1.5s. Navigating or an address change clears the flag, so ordinary navigations and the ad block toggle's reload never show it.
- Edge badge: `main_frame_headers_received` sets `Tab.edge` from `EdgeHeaders` (`Sources/MiniRules`, unit tested with live vercel.com, nextjs.org and cloudflare.com header samples): Vercel when `x-vercel-id`/`x-vercel-cache` or `server: Vercel` (cache status, the edge region and, when the id has two regions, "edge → function", then `x-nextjs-cache` and age), Cloudflare from `cf-ray`/`cf-cache-status`/`server: cloudflare` (cache status and the ray's colo), a bare `x-nextjs-cache` as Next.js; anything else has no badge. The vitals popover shows it as a caption chip under the values ("Vercel · HIT · sfo1 → iad1 · age 2m").
- Localhost dev tabs (`LocalDevelopment` in `Sources/MiniRules`, unit tested): http(s) pages on localhost, `*.localhost`, 127.0.0.0/8 and `[::1]` get a "dev :port" chip instead, and their sidebar row shows a tertiary ":port" label while hovered. `LocalServers.swift`: while the command bar is open (on open and on every keystroke, cached 5s) `LocalServerScanner` runs `lsof -nP -a -iTCP -sTCP:LISTEN -u <own uid> -F pcn +c 0` on a detached task, keeps listeners reachable through loopback (`*`, `0.0.0.0`, `::`, `127.x`, `::1`), drops Mini itself, system paths (`/System`, `/usr/libexec`, `/usr/sbin`, `/sbin`) and installed apps directly in `/Applications` or `~/Applications` (except their `Contents/Developer` toolchains), then keeps the ports that answer a 0.6s `HEAD http://localhost:<port>/` (ephemeral session, no cookies). Empty-query rows list them under "Local Servers" ("next-server · 3000", Open); typed queries match process name and port. ":3000" always opens http://localhost:3000; a bare "3000" does only while a server listens there, so numeric searches still search.
- `DevServerReconnect.swift`: a main-frame `main_frame_load_failed` with ERR_CONNECTION_REFUSED (-102) on a local address sets `Tab.devServerWait` and the page overlay (`CrashOverlayController`, which also shows crashes) shows a quiet "Waiting for localhost:3000" with a small spinner while a task probes the port (HEAD) after 0.25, 0.5, 1, 2, then every 4s up to 60s in all (`LocalDevelopment.retryDelays`); the first answer clears it and loads the failed URL again. After 60s it reads "localhost:3000 is not answering" with Try Again. Navigating elsewhere, an address change to another URL and closing the tab cancel it. Other load errors are left to Chromium's page.
- Preview and production pairs (`PreviewSwitching.swift`): View > Switch to Production / Switch to Preview (Shift-Cmd-P, main window) navigates the selected tab to the same path on the counterpart host. A preview's project pairs with a production host whose first label or registrable domain's first label is the project (or `project.vercel.app`), and the pair is only ever taken from the current space's history (most recent first), so a production domain that was never visited is never guessed; with no pair the item is disabled. Its key equivalent is uppercase `"P"` with `[.command]`, not `"p"` with `[.command, .shift]`: AppKit's menu matching compares a lowercase key plus Shift against the event's `characters`, which a real keyboard gives as `p` for Shift-Cmd-P but an event carrying `P` (synthesized ones, some layouts) does not, while the uppercase form matches both.
- `InterfaceMetrics.swift` is the one place for sidebar and command bar metrics: `SidebarMetrics` (28pt rows, 8pt edge inset and row radius, 16pt indent, icon and accessory sizes, pill, tile, footer and space bar spacing) and `CommandBarMetrics`, every spacing on a 4pt grid, plus `CornerMetrics` (the window's measured 26pt corner radius and 8pt glass inset, both fixed, and the concentric rule used by the page card, peek sidebar, docking outline, command bar rows, Now Playing artwork, split halves and the tear-off preview's page) and `InterfaceFont` (13pt body, 11pt caption and semibold section headers, symbols at three weights: row 13 regular, control 12 medium, accessory 10 semibold). Tab favicons sit at the row indent plus the 12pt disclosure column; footer rows (Now Playing, weather, downloads, New Tab) put their 16pt icon column at 8pt so their text lines up at 32pt. Pinned glass tiles; `SplitTabRowView` is the joined split row with a half per tab, the focused half highlighted; row context menu "Open in Split View".
- Interface Size (View > Interface Size: Larger Interface Ctrl-Cmd-=, Smaller Interface Ctrl-Cmd--, Actual Interface Size Ctrl-Cmd-0, never page zoom) scales Mini's own UI: `InterfaceScale.shared` (`@Observable`, level persisted as `interfaceSizeLevel` in UserDefaults) is the one source, and every `SidebarMetrics`, `CommandBarMetrics`, `OverlayMetrics` and `InterfaceFont` value is a computed property that reads it through `InterfaceScale.scaled` (rounded to 0.5pt), so SwiftUI bodies that read a metric re-render on change. Pure levels (85, 92, 100, 108, 117, 125%), clamped stepping and the proportional sidebar width live in `Sources/MiniRules/InterfaceSize.swift`, unit tested. The window corner (26) and the glass inset (8) do not scale, so `CornerMetrics.sidebarGlass` stays concentric with the window; `playerSlot` follows the scaled edge inset. AppKit parts read metrics when shown (toast, tooltip) or on `applyInterfaceScale` (command bar constraints and fonts, little window address field, sidebar min/default/max width with the current width scaled proportionally, the peek sidebar width). The change runs in a 0.18s `withAnimation`, none with Reduce Motion. Main window toolbar buttons stay fixed beside the traffic lights.
- `SiteTintView.swift`: background of `SidebarView` (so the sidebar and the peek sidebar): the space color at 10% (13% in dark mode), animated 0.3s on switch, under the selected tab's `Tab.themeColor` at 20% (times the color's alpha), animated 0.25s, so the theme color blends over the space tint and never hides it. Under both sits the evening tint: a warm amber (1, 0.6, 0.22) at up to 6% (7% in dark mode) times `ShellController.eveningTintStrength`, animated 3s per change. The strength is `EveningTint.strength` (`Sources/MiniRules/EveningTint.swift`, unit tested in `Tests/MiniRulesTests`) over the weather reading's `sunrises` and `sunsets` at `eveningTintDate`, which the 10 minute archive timer advances (no timer of its own): 0 by day, 1 at night, a smoothstep over the 20 minutes centered on each sunset and sunrise, and 0 with no reading or when the time is more than a day outside the reading's sun times. View > Evening Tint (`showsEveningTint`, UserDefaults `ShowsEveningTint`, on by default) turns it off. All three clear with Reduce Transparency or with Increase Contrast. The fill stays inside the floating glass sidebar's rounded shape.
- `SidebarKeyboard.swift`: sidebar keyboard focus. `ShellController.sidebarKeyboard.focusedTabIdentifier` drives `SidebarFocusRing` (the shared `FocusRing` on rows, split rows and pinned tiles; the focused row gets `zIndex` 1 so its outset ring draws over its neighbors). Entry: a tap on empty sidebar space (the outer background and the tab list's `ScrollView` background) or Tab (a local keyDown monitor, only while the window's first responder is the window itself or nil, so pages and text fields keep Tab). `SidebarHostingView.acceptsFirstResponder` is true only while `allowsKeyboardFocus` is set by `focusSidebar()`, so clicking rows never takes focus from the page; it resets on resign, which also clears the ring. Order is the Player, pins, then `visibleTabs`; ↑↓ move, ←→ collapse/expand or go to parent/first child (on pins they move), Return selects and focuses the page, Delete closes and moves the ring to the next surviving item, Esc/Tab return to the page. Modified keys go back to AppKit, so menu key equivalents (performKeyEquivalent runs before keyDown) still work while the sidebar is focused (verified with Cmd-T). The focused row is scrolled into view with a `ScrollViewReader`. Main sidebar only, not the peek sidebar.
- `Downloads.swift`: `DownloadsModel` (active downloads plus ones finished in the last 10 s) and the sidebar `DownloadRowView` (click cancels while active, reveals in Finder when complete).
- `NowPlaying.swift`: `AudioToggleButton` (speaker on playing or muted rows and pinned tiles, toggles mute) and `NowPlayingRowView` above the weather row for `ShellController.nowPlayingTab` (the tab that most recently started playing; kept while paused from the row), with play/pause and click-to-select. Its title is `Tab.mediaTitle`, set from every `audio_state_changed` (so it follows the tab's current page and clears when that page has no metadata), else `displayTitle`. The row shows a 22pt rounded artwork thumbnail (`Tab.mediaArtwork`, else the favicon on a quaternary fill) and fills its background with the artwork's dominant color (`Tab.mediaArtworkTint`, computed once when the artwork is set; the favicon's when there is no artwork) at 22%, animated 0.4s, off with Reduce Transparency or Increase Contrast. Playing tabs are passed to `ArchivePolicy` as selected, so they are never archived.
- Player slot (`PlayerSlotView.swift`, `PlayerDock.swift`, pure rules in `Sources/MiniRules/PlayerSlot.swift`, unit tested): the space's Player tab sits above the pinned tiles; with none, `EmptyPlayerRow` (the cached YouTube favicon, else a red `play.rectangle.fill`, and "Player") holds the place unless the slot is hidden (tabs-and-undo.md). `Tab.playerPhase` is `.idle` or `.docked`; leaving the selected Player while it plays audibly sets `.docked` (`PlayerSlot.phase(afterLeavingWhilePlaying:)`), the slot's close button sets `.idle` after pausing every media element. `PlayerSlot.presentation` maps phase, selection and `PlayerDock.sidebar` (expanded, peeking, hidden) to `.page` (selected: the normal page), `.row` (idle: a 28pt glass row with the favicon and "Player"), `.slot` (docked: a 16:9 placeholder at sidebar width, corner `CornerMetrics.playerSlot`) or `.pictureInPicture` (docked while the sidebar is fully collapsed).
  - The docked browser is the same live host view moved into a `PlayerDockPanel`: a borderless child window of the main window (above the floating glass sidebar, the page card and the peek panel, so one parent serves both sidebars and the move between card and slot can animate), an `NSGlassEffectView` rim 1.5pt around a clipped video view and a SwiftUI controls layer. The placeholder reports its `.global` frame, which is window content coordinates from the top (not hosting-view coordinates: converting through the hosting view put the panel 8pt off), per sidebar kind; only the current space's slot reports.
  - `refreshDisplayedTabs` never hides the tab `tabToDock` returns, then `PlayerDock.update` docks it (injecting the dock style, creating the browser for a lazy Player) or releases it (back into the web area, hidden, style removed). Selecting the docked Player calls `undock`: the panel flies back to the page card and `display` waits for it (`awaitsHostView` keeps the empty page hidden) before taking the host view. Flights are 0.3s ease in-out with the corner radius animated alongside, only for selection changes; Reduce Motion crossfades the panel instead.
  - Page side, all through `javascript:` URLs (`PlayerScripts`, verified on youtube.com): the dock style marks the playing (else the largest started) video `data-mini-player`, clears transform, filter and contain on its ancestors and makes it fill the viewport over a hidden page; it is re-applied when a docked page finishes loading and removed on undock. Hover controls (an `.activeAlways` tracking area sets `PlayerDock.isHovered`): Picture in Picture, close video, back and forward 10s, play/pause, glass circles with the shared hover highlight; a click elsewhere on the video selects the Player (`toggle` haptic; auto-dock on a tab switch is silent). The hover dim is the tap layer's own fill under the controls, never a background on the controls: as a background it covered the whole video and swallowed the click while hovered, so the docked Player could not be expanded.
  - Sidebar fully collapsed: the panel goes transparent and the video enters native Picture in Picture; expanding or peeking exits it and shows the slot again (the peek slot reports from the peek hosting view). `ShellController.nowPlayingRowTab` hides the Now Playing row for the Player while its slot shows, falling back to another playing tab. The link context menu offers "Play in Player" for YouTube video links (`PlayerSlot.isYouTubeVideo`), loading the link into the Player (making one if needed) and docking it when it is not selected.
- `AirPlay.swift`: the row's AirPlay control, left of play/pause.
  - When the tab's `mediaVideoURL` is set (the playing video's own http(s) source, from `audio_state_changed`), it is an `AVRoutePickerView` bound to the one app-lifetime `AirPlayVideo.player` (`allowsExternalPlayback`), so the chosen device stays selected while Mini runs. Opening the list loads the URL into the player; when `isExternalPlaybackActive` turns true, `mini_browser_hand_off_video` pauses the page (`isPausedFromNowPlaying` keeps the row) and `video_handed_off` gives the position the player seeks to before playing. While handed off, the row's play/pause drives the player. External playback ending takes back the position and play state with `mini_browser_take_back_video`; the page playing again, a new source or closing the tab just stop the player.
  - Otherwise (MediaSource, blob and stream video such as YouTube, and audio) it is an `airplayaudio` button with a menu: "Sound Output…" and "Mirror Display…" open the Sound and Displays settings panes. It takes the space accent while the Mac's default output device is AirPlay (`SoundOutput` listens to `kAudioHardwarePropertyDefaultOutputDevice`).
  - Why: Chromium renders through CoreAudio on the default output device, and an AirPlay speaker only becomes a CoreAudio device once the system output selects it (none is listed otherwise, even with receivers on the network), so Mini cannot route only its own page audio there; Chromium follows default device changes and adds the device latency for A/V sync, so the system output path works. `AVRoutePickerView` without a player lists only AirPlay receivers and routes the app's AVFoundation output context, not CoreAudio clients; the macOS SDK documents routing for `AVPlayer` only. MediaSource video has no URL a receiver can fetch, and there is no public API to start mirroring.
  - Background test instances cannot open `NSMenu`s reliably, so the fallback menu is untested visually; the route list opens with `accessibilityPerformPress`.
- Favicon contrast: setting `Tab.favicon` measures it once into `Tab.faviconTone` (`FaviconTone.measure` in `Sources/MiniRules`, unit tested: alpha-weighted relative luminance of the unpremultiplied pixels and alpha coverage over the 24x24 `DominantColor` sample). `FaviconView` (given a tone: tab rows, split halves, pinned tiles, command bar tab rows) draws a soft rounded plate 2pt outside the icon only when a mostly dark icon (luminance under 0.12, coverage at least 5%) sits in dark mode (white at 45%) or a mostly light one (over 0.8) in light mode (black at 25%); +30% with Increase Contrast or Reduce Transparency. Colorful icons never qualify. A favicon that arrives from the page (`faviconChanged` sets `Tab.faviconArrivedLive`) crossfades in from the globe placeholder over 0.15s in tab rows, split halves and pinned tiles; cached favicons set at restore appear without a fade.
- Unread badges: `Tab.title` stays the page's real title (history, session, search); `Tab.unread` comes from `UnreadBadgeTracker` (`Sources/MiniRules/UnreadTitle.swift`, unit tested) on every title change. `UnreadTitle.parse` reads a count only at the start ("(3) Inbox", "[3] Chat", "3 unread", a "\u{2022}" or "* " dot prefix meaning unread without a count) or at the very end in parentheses ("Inbox (3)", 4-digit years refused), plus, on messaging sites only, a parenthesized count right before a " - " separator (Gmail's "Inbox (3) - me - Gmail"). The tracker only reports it when the host is a messaging site (`isMessagingSite`: Gmail, Google Messages, Outlook, Slack, Discord, Linear, github.com/notifications) or the count changed on the same title while the tab stayed on that host (a new host resets it). `displayTitle` drops the count. `UnreadBadgeView` sits centered on the favicon's top-trailing corner of rows, split halves and pinned tiles (12pt on rows, 16pt and pushed further out on tiles): a space-accent capsule with white rounded digits capped at "99+", or an accent dot, with a 1.5pt background ring; zero shows nothing. `titleChanged` bumps `Tab.unreadPulses` when the count rises (or a badge appears) on a tab that is not displayed, which plays one 1.25x scale keyframe pulse; Reduce Motion freezes the trigger. No sound or notification.
- `DominantColor.swift`: pure `color(of:)` over a 24x24 sRGB downsample: opaque pixels bucketed at 3 bits per channel, weighted by saturation (near-black pixels count little), the heaviest bucket's average wins.
- `WeatherService.swift`, `WeatherRowView.swift`: sidebar weather row. CLLocationManager with `kCLLocationAccuracyReduced`, authorization requested lazily at launch (denied or restricted hides the row and clears the cache, no re-prompt), coordinates rounded to 2 decimals, Open-Meteo forecast (fahrenheit when `Locale.current.measurementSystem == .us`), place name from `MKReverseGeocodingRequest` (`CLGeocoder` is deprecated in the macOS 26 SDK and would warn), WMO code to SF Symbol mapping in `WeatherCondition.forCode` (pure, day/night variants), refresh every 30 min and on `NSWorkspace.didWakeNotification`, last reading cached in UserDefaults `WeatherReading`; failures keep it, no cache hides the row. Click opens a "weather" search tab. The request asks for `forecast_days=7` with daily `weather_code`, `temperature_2m_max/min`, `precipitation_probability_max`, `sunrise`, `sunset`, stored as `WeatherReading.days` and `sunrises`/`sunsets` (local ISO times parsed in the response's `timezone`) in the same cache (a cache from before `days` or the sun times existed fails to decode and is refetched).
- `WeatherWeekView.swift`: `WeatherPopoverPresenter` (owned by ShellController, shared by the sidebar and the peek sidebar) opens an `NSPopover` (`.applicationDefined`, `animates` off with Reduce Motion) at the row's `WeatherAnchorView` (beside the row when the whole popover fits 16pt inside the window vertically, otherwise above it with the positioning point moved right so the popover's left edge stays inside the window; the popover is a child window, so AppKit only keeps it on screen, not in the window) 0.4s after the row is hovered, and closes it 0.15s after the pointer is over neither the row nor the popover, or on click. `WeatherWeekView`: city, current temperature and condition, then 7 rows (Today/short weekday, multicolor symbol with precipitation chance at 30% or more, low, a range bar placing the day within the week's low-high span, high) over a 75% window-background tint so it reads over white pages.

## Command bar

- `CommandBarController.swift`, `CommandBarModel.swift`, `CommandSuggestionsView.swift`: the floating command bar. A 760pt regular glass panel with a 55% window-background tint plus a `CommandBarBackingView` filling it with window background at 72% so busy pages do not show through (the glass tint alone barely changes how much of the page shows, and the adaptive glass turned dark over saturated pages even in light mode), radius 20, centered on the web area, width min(760, web area minus 32, window minus 80).
- Entrance: `OverlayAnimation.appear(glassView, scale: 0.97, blurring: content)` springs it in from 97% with a fade and a 6pt Core Image blur on the content that clears over 0.18s (the filter is removed afterwards); it leaves with the shared 0.12s fade, faster than it enters. Reduce Motion: fade only. The results' height is an explicit required constraint on the suggestions hosting view, set from its `intrinsicContentSize` on the next main-queue turn after every model change and animated with `NSAnimationContext` (0.18s ease-out, retargeting while typing; instant with Reduce Motion); the rows themselves still update with animations disabled, so unchanged rows never re-animate.
- Rows: open/search row first, up to 4 Google suggestions, matching tabs, History rows, then Archived; recent tabs on empty Cmd-T; Cmd-Return opens in background. Typing updates run in a transaction with animations disabled, row ids are stable (the open row is always `open`) and the selection follows its item id.
- `PastedLinks.swift`: pure `PastedLinks.parse`: http(s) URLs in order from any text, exact repeats dropped, trailing `)]}>,.;:!?'"` stripped, and a URL alone on its line takes the non-URL line directly above as its title (Safari "Copy Links" shape). In the command bar, Cmd-V with 2+ links (`CommandField.onPaste`, read from the general pasteboard) keeps the raw text in `CommandBarController.pastedText` and shows "N links pasted" in the single-line field; editing the field drops the raw text, and typed text with 2+ URLs also qualifies. The model then shows only `.openLinks` ("Open N Links") with up to 6 non-selectable preview rows plus "+N more". Return opens them via `ShellController.openLinks` as lazy tabs after the selected tab with their pasted titles, selecting (and so loading) only the first; Cmd-Return opens them without changing selection; Option-Return (`insertNewlineIgnoringFieldEditor:`) nests the rest under the first link (there is no group-tab concept).
- `SearchSuggestions.swift`: Google suggest (`suggestqueries.google.com/complete/search?client=firefox`) parsing (pure `parse`) and `SearchSuggestionFetcher` (URLSession, 120 ms debounce, previous request cancelled per keystroke, responses for a stale query dropped, failures silent, nothing logged). Skipped for empty input or anything `URLInput` reads as an address.
- `URLInput.swift`: host and insecure checks; input to URL or search is `AddressInput` in `Sources/MiniRules` (search template, http for localhost, `*.localhost`, IPv4 and bracketed hosts, https for dotted hosts whose last label has a letter, everything else searches).
- Actions (`CommandActions.swift`): a leading `>` switches the bar to menu commands. The list is generated from `NSApp.mainMenu` on every keystroke (each submenu `update()`d first so validation sets titles, enabled and checkmark state; separators, hidden items, the edit actions, Select Tab N, New Tab and Open Location are skipped; nested submenu items are titled "Space Color: Blue"), fuzzy matched with `FuzzyMatch` (`Sources/MiniRules`, unit tested: subsequence match scored for word starts, runs and an early first match) and capped at 10 rows. Recently run actions (UserDefaults `RecentCommandActions`, ids from selector, tag and represented object, last 8) rank first. Rows show the menu item's image (or the `command` symbol), the title, a checkmark when the item is on, and the shortcut (`KeyEquivalentText`, unit tested); disabled items are dimmed and Return does nothing on them. Return closes the bar and performs the item on the next main-queue turn after a fresh validation; a click also plays `press`, the keyboard nothing. Commands added for it: Edit > Copy as Markdown Link (Opt-Cmd-C, `[title](url)` with brackets escaped and parentheses percent-encoded), File > Open in Safari (http(s) only, through `NSWorkspace.open(_:withApplicationAt:)`), Tabs > Archive Tab (the selected or multi-selected tabs, like the row menu).

## Overlays on the page

- `OverlayAnimation.swift`: shared appear (fade plus spring scale, fade only with Reduce Motion) and disappear for overlays.
- `FindBarController.swift`: find-in-page capsule.
- `StatusBubbleController.swift`: link hover bubble. `on_status_message` -> `status_message_changed` (the hovered or focused link's URL, "" on leave); only tabs in `displayedTabs` show it. A small glass capsule at the web area's bottom-left (8pt inset, at most half the web area wide, middle truncation) that moves to the bottom-right when the pointer is within 24pt of where it would sit; an empty status fades it out after 0.25s, a tab switch hides it at once.
- `ToastController.swift`: transient glass toast at the bottom of the web area (Copy URL shows "Copied", zoom shows the percentage).
- `ErrorPages.swift`: Mini's own error pages. `main_frame_load_failed` also goes to `showErrorPage`, which classifies the net error with `LoadErrorPage` (`Sources/MiniRules`, unit tested): offline (-106), host not found (-105, -137), refused (-102, except local addresses, which the dev server wait in `DevServerReconnect.swift` owns), reset (-101, -100, -324), timed out (-118, -7), blocked by the client (-20) and certificate errors (-200 to -299); anything else (including -3 aborts) keeps Chromium's page. Each page has an SF Symbol in the space accent (rendered to a PNG data URL), a one-line title, one line of detail and Try Again, plus Go Back when there is history; colors are the window background and label colors resolved for the window's appearance. The HTML goes to `mini_browser_show_error_page`. Offline pages register with `OfflineRetry` (an `NWPathMonitor` started on first use), which reloads each waiting tab still on its failed URL when the path becomes satisfied. Certificate errors commit no document Mini can write into, so they show in the page overlay instead (`PageOverlayContent.certificateError`, from `Tab.certificateErrorPage`, cleared when the tab starts loading), with Go Back as the primary action and Try Again second. There is no way to proceed past a certificate error, as before.
- `CrashOverlayController.swift`: "This page crashed" overlay over the web area for the selected tab when `render_process_terminated` marked it; Reload calls `mini_browser_reload`, the next loading start clears it, and a crashed background tab reloads when selected. The same overlay shows the localhost wait (`PageOverlayContent`).
- `SitePromptController.swift`, `SitePromptViews.swift`: per-tab queued permission and HTTP auth cards over the web card; `FaviconView`.
- `LoginFillController.swift`, `LoginFillCardView.swift`: password fill card, shown only on Cmd-\ (Fill Password) or the address pill's key button (visible while `Tab.hasLoginForm`) via `mini_request_login_fill`, never automatically (AppKit NSTextField/NSSecureTextField with username/password content types so macOS Passwords AutoFill attaches); values are never stored and are cleared on every close.

## Page features

- `PageContextMenu.swift`: the native page menu, popped up on the next main-queue turn at the CEF coordinates in the tab's web view. Sections: spelling suggestions plus Learn Spelling (editable with a misspelled word), link (Open Link in New Tab as a child, Open Link in Split View, Copy Link), image (Open Image in New Tab, Copy Image, Save Image As... through an NSSavePanel sheet), editable (Cut/Copy/Paste/Select All enabled from the edit bits), selection when not on a link (Copy, Look Up via `showDefinition`, Search for), Back/Forward/Reload/View Source only on the bare page, Inspect Element last. Little-window tabs get the same menu; their new tabs go to the main window and split is disabled.
- `SourceWindowController.swift`: View > View Source (Opt-Cmd-U), the page menu's View Source and the `>` action open the selected tab's main-frame source (`mini_browser_request_source`, no network request) in a little source window of its own (900x680, cascaded from the main window, never a tab). A read-only TextKit 1 `NSTextView` (`allowsNonContiguousLayout`, so only the visible part is laid out) in Geist Mono 12 when `GeistMono-Regular` is installed, else the system monospaced font (SF Mono). `SourceHighlighting` (`Sources/MiniRules`, unit tested, UTF-16 offsets) tokenizes HTML (tags, attributes, values, comments, doctype, entities) and the contents of `<script>` (keywords, strings, comments, numbers) and `<style>` (at-rules, properties, strings, comments, numbers) on a detached task together with the line starts; colors are applied in batches of 20,000 tokens per main-queue turn (a 6 MB page kept the main thread's worst gap at 85 ms). System colors keep both appearances. `LineNumberRulerView` draws numbers for the visible lines only. A toolbar toggle wraps lines (UserDefaults `SourceWrapsLines`, on by default); Cmd-F, Cmd-G and Shift-Cmd-G go to the text view's find bar while a source window is key.
- `NavigationHistory.swift`: session history menus. `mini_browser_visit_navigation_entries` (CefNavigationEntryVisitor; CEF visits synchronously on the UI thread, Rust collects then calls the C visitor) gives every entry oldest first; back lists older entries newest first, forward the newer ones, each with its cached favicon and title. Picking one calls `mini_browser_go_to_history_offset` (`history.go(n)` in the main frame). `HistoryButton` opens the menu on right-click or a 0.4s press, otherwise sends its action on mouse-up inside. Main window only; the little window's buttons are plain.
- `SwipeNavigationController.swift`: two-finger swipe back/forward in the main window. A local `.scrollWheel` monitor tracks phase-based precise scrolls over the selected tab's host view (only when `NSEvent.isSwipeTrackingFromScrollEventsEnabled`, i.e. AppleEnableSwipeNavigateWithScrolls, and no sheet). The first 12pt of travel go to the page; then, if the gesture is mostly horizontal, the tab has history that way and `Tab.horizontalScrollRoom` says the page cannot scroll toward it, the controller takes over: it consumes the rest of the gesture and its momentum, slides a 44pt glass `SwipeIndicatorView` arrow in from that edge of the web area (accent tinted once travel reaches 140pt) and navigates on release past that point. Direction is physical: fingers right is back, using `isDirectionInvertedFromDevice`. Little windows have no swipe.
- `ShellFullscreen.swift`: page (element) fullscreen. `fullscreen_mode_changed(true)` from the selected main-window tab records a `PageFullscreen` (tab, whether the sidebar was visible, whether Mini entered native fullscreen), collapses the sidebar item, hides the toolbar, shows only that tab through `refreshDisplayedTabs` (a split shows just the fullscreen side) and enters native fullscreen unless the window already is. Entering from a windowed state animates first: the sidebar collapses through the split item's animator and the card's insets go to zero (`setPageFillsWindow(_:animated:)`, 0.25s ease-in-out, CEF resized every frame), so the page grows from its card to the whole window, and only then does `toggleFullScreen` run; leaving reverses it while the window leaves native fullscreen. Reduce Motion skips the animation. It grows from the page card's frame, not the video element's rect. `false` restores all of it and leaves native fullscreen only if Mini entered it. Selecting another tab, closing the tab, or the user leaving native fullscreen calls `mini_browser_exit_fullscreen`, then restores. Little-window tabs are ignored (the page fills the little window).
- `NotificationsController.swift`: UNUserNotificationCenter delivery (title, host as subtitle, body, favicon-cache attachment, no sound when `silent`, a `tag` replaces the same-origin notification with that tag), `close()` removes the delivered one, clicks activate Mini, select the tab only if it still shows the same origin, and call `mini_notification_clicked`. macOS authorization (alert, sound, badge) is requested the first time a site is granted; if macOS denies it, nothing is shown and one content-free line is logged. SitePreferences pushes each origin's notification state to Rust at launch and on every decision; View > Allow Notifications from This Site toggles it.
- `SitePreferences.swift`: per-origin permission decisions (permissions.json), ad block exempt hosts (adblock-exempt.json) and per-host zoom levels (zoom-levels.json, CEF zoom units, factor 1.2^level). `mini_browser_zoom` returns the new level; the shell stores it for the host, applies it to other open tabs on that host, and re-applies it through `mini_browser_set_zoom_level` whenever a tab's host changes (address_changed). Cmd-0 removes the entry. A toast shows the percentage.
- `SiteBackgroundCache.swift`: each host's page background, so a page that has not painted yet shows its site's color instead of white. The theme-color script also reports, after the load event, the main frame's opaque computed body background, else the html element's, else the theme-color, else white unless the page's `color-scheme` is dark (`page_background_changed`, 0xRRGGBBFF). `SiteBackgrounds` (`Sources/MiniRules`, unit tested) keeps the last 500 hosts, most recent last, stored as `site-backgrounds.json` beside `Favicons/` (outside it, because the favicon prune deletes unknown files there). `ShellController.startBrowser` passes the host's color, or the window background resolved for the current appearance for an unknown host, to `mini_browser_create` (CEF's `background_color`, shown until first paint) and sets it as the `BrowserHostView` layer background, which shows before the CEF view is attached. Measured: without it a lazily created tab showed one white frame on selection.
- `FaviconCache.swift`: favicon PNGs cached at `Favicons/<sha256 of host>.png` (written on a utility queue, skipped when the bytes are unchanged), loaded for any tab or pinned tile without a live favicon (pinned tabs by `pinnedURL` host) at restore and on every structure change, used by archived command-bar rows; pruned once per launch to hosts of open, pinned and archived tabs, capped at 500 files.
- `DefaultBrowser.swift`: default-browser check and registration for http and https.
