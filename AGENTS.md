# Mini

A minimal personal macOS browser: native Swift shell (AppKit window, SwiftUI sidebar, Liquid Glass) around Chromium via CEF, embedded from a Rust core using the `cef` crate (tauri-apps/cef-rs). Arc-style vertical sidebar with nested (tree) tabs. Single main window (plus little windows for outside links), spaces with separate profiles, no extensions, sync or accounts. Target: macOS 26+, Apple Silicon. README.md has build and run steps.

## Architecture

```
Mini.app/Contents/MacOS/Mini            Swift executable (shell/), statically links libmini_core.a
  main.swift: MiniApplication (NSApplication + CefAppProtocol) -> mini_initialize -> mini_run_message_loop -> mini_shutdown
Mini.app/Contents/Frameworks/
  Chromium Embedded Framework.framework   loaded at runtime by cef_load_library (never linked)
  Mini Helper{, (GPU), (Renderer), (Plugin), (Alerts)}.app   all copies of the Rust mini-helper binary
```

- Swift owns: window, sidebar, tab tree, selection, command bar, menus and key equivalents, focus decisions, session persistence. Tab ids are minted in Swift.
- Rust owns: CEF init/shutdown, the tab-id -> Browser map, every CEF handler (display, load, life span, request, keyboard, focus, download, permission, context menu). It never draws UI.
- The boundary is the C ABI in `core/include/mini_core.h`, nothing else. Rust calls back through the `MiniCallbacks` function-pointer table; Swift calls `mini_*` functions.
- Each tab has a `BrowserHostView` (NSView). CEF creates the windowed (non-OSR) browser NSView as its subview; the host view sizes subviews to its bounds. Switching tabs swaps which host view is visible and calls `mini_browser_set_hidden`.
- Spaces: `ShellController.spaces` holds `Space` objects (id, name, SF Symbol, `usesDefaultProfile`, its own `TabStore`); `store` is always `currentSpace.store`. Tab ids come from one shared `TabIdentifierMint`, so ids are unique across spaces and callbacks find a tab's space with `space(containing:)`. Each space maps to a CEF request context registered in Rust with `mini_space_create` before any of its browsers exist; the default-profile space uses the global context (`Profile/Default`), the rest `Profile/Spaces/<id>`.
- Browsers are created lazily: restored tabs have no browser until first selected (or shown as the other side of a split).
- Split view: `TabStore.splits` holds `TabSplit` pairs (leading, trailing, fraction) of unpinned tabs; `selectedTab` is always the focused side. `ShellController.refreshDisplayedTabs` is the only code that shows or hides host views: it shows the selected tab plus its split partner, hides everything else it showed before, and hands `WebAreaView` a `SplitArrangement`.

## Invariants

- Everything CEF runs on the main thread (CEF UI thread = main thread on macOS, `cef_run_message_loop` drives NSApp). Never use multi_threaded_message_loop or external_message_pump.
- NSApp must be `MiniApplication` (conforming to ObjC protocols named CrAppProtocol, CrAppControlProtocol, CefAppProtocol) before `mini_initialize`. Nothing may touch `NSApplication.shared` earlier.
- Quit flows through `MiniApplication.terminate(_:)`: save session, `mini_close_all_browsers`, wait for `all_browsers_closed`, then `mini_quit_message_loop`. Never `exit()` with live browsers.
- Browsers use the Alloy runtime style (content only, no Chrome UI); the shell draws all chrome.
- App shortcuts beat the page: `pre_key_event` hands Cmd/Ctrl key-downs to Swift, which runs matching browser-command menu items and consumes them. Edit-menu shortcuts (copy, paste, undo, select all) are never consumed there.
- Popups with an opener are parented into a new child tab via `popup_requested` (keeps OAuth popups working); opener-less new-tab links use `open_tab_requested`.
- Login fill: password and username values from the shell are never logged, persisted or echoed (including under `MINI_ADBLOCK_LOG`); Rust zeroizes the script strings it builds from them. The origin passed to `login_field_focused` and checked by `mini_fill_login` is always derived browser-side from the frame's committed URL (http/https only); nothing in the page's console signal except the frame id is trusted, and the frame id is verified with `frame_by_identifier`.
- Notification titles, bodies and tags are never logged.
- The C header is the contract: change it, then both sides, in the same commit.
- Auto-archive never closes the selected tab or pinned tabs, and only closes a parent after all its children qualify; it is the only code path that closes tabs without user action besides `browser_closed`.
- Little windows: `ShellController.littleWindows` (tab id -> controller) is the registry; `BrowserEvents.liveTab` looks there after the store, so every engine callback reaches little-window tabs. They are never in `TabStore`, session.json, the archive or Now Playing. Links stay in the window; `open_tab_requested` (Cmd-click) from one creates a main-window root tab; a popup with an opener gets its own little window. Permission and auth requests from little tabs are answered by remembered decisions or denied (the prompt cards only exist in the main window).
- Promote (Open in Mini, Cmd-O) reparents the live browser: the tab's host view (with CEF's NSView inside) moves from the little window into `webAreaView` and the same `Tab` object is `TabStore.adopt`ed as a root tab after the selected root, then selected. Verified: page JS state survives (a random number written at load and a running timer continue unchanged after the move, no reload). The little window then closes without `mini_browser_close`.
- Menu commands resolve their target from the key window: with a little window key, Cmd-W closes it, Cmd-L edits its address, and back/forward/reload/stop/zoom/devtools/PiP/Copy URL act on its tab (`commandBrowserTab`); find and Fill Password stay main-window only.
- Only the current space's store drives the window: `tabStore(didSelect:)` and `tabStoreDidChangeSplits` ignore other stores, and `switchToSpace` hides the old space's shown tabs and shows the new one's through `refreshDisplayedTabs`. Background spaces keep their browsers running (title, audio, downloads, notifications still arrive); `reveal(_:)` switches space before selecting (Now Playing, notification clicks).
- The default-profile space is never deletable (it holds the user's original cookies and logins), and the last space can't be deleted either. Deleting a space closes its tabs and little windows, waits for those browsers' `browser_closed`, then calls `mini_space_destroy` and removes `Profile/Spaces/<id>`; launch also sweeps `Profile/Spaces` for folders of spaces that no longer exist. Nothing outside `Profile/Spaces` is ever deleted.
- session.json is `{spaces: [{id, name, symbol, usesDefaultProfile, contents: {tabs, selectedPath, pinnedTabs, selectedPinnedIndex, splits}}], currentSpace}`. A file in the pre-spaces shape (top-level `tabs`) is migrated once at load into Personal (person.fill, default profile) plus an empty Work (briefcase.fill), and launch immediately saves the new shape; the old shape is never written.
- A tab is in at most one split. Closing or pinning either side removes the split (`tabStoreDidChangeSplits` then re-arranges); the partner of the selected tab counts as selected for auto-archive.
- Split focus follows clicks through a local mouse-down monitor (hit-testing into the partner's host view), not CEF focus callbacks: `focus_requested` refuses focus for every tab but the selected one, so the partner page never focuses itself.
- Style: no comments unless a genuine trap, full-word names, no em/en dashes, no AI attribution anywhere.

## File map

- `core/include/mini_core.h`: the C ABI.
- `core/Cargo.toml`: workspace (edition 2024, `cef = "=156.2.0"`, release `panic = "abort"`). `core/.cargo/config.toml` pins `MACOSX_DEPLOYMENT_TARGET=26.0` so C deps (ring) do not target the SDK version.
- `core/mini-core/`: Rust staticlib (`libmini_core.a`) implementing the ABI.
  - `src/lib.rs`: the `#[unsafe(no_mangle)]` ABI functions and the `#[repr(C)]` mirrors of the header types; library loader static.
  - `src/state.rs`: main-thread `thread_local` state (callbacks table, space id -> `RequestContext` map filled by `mini_space_create` and used by `mini_browser_create`, tab id -> `TabState` with `Option<Browser>` + pending url/focus/hidden/close + favicon generation, pending popup ids, reported download ids, closing-all flag); the global request-id counter shared by permissions and auth.
  - `src/client.rs`: `MiniClient` (one per tab, carries the tab id) and the display, load (cosmetic injection at `on_load_start`), life span, request (open-url, auth, resource handler), keyboard, focus and download handlers; `DevToolsClient` (no handlers) for devtools windows. Tab close dismisses pending permissions and cancels pending auth.
  - `src/favicon.rs`: `download_image` of the first favicon URL, PNG at scale 2 via `Image::as_png`; per-tab generation drops stale or closed-tab results.
  - `src/permissions.rs`: `MiniPermissionHandler`; CEF media and prompt bits <-> `MiniPermission` bits; pending requests keyed by request id (main thread). Origins are sent as `scheme://host[:port]`.
  - `src/authentication.rs`: `auth_credentials` runs on the IO thread: callback stored in a `Mutex` map, `auth_requested` delivered by a task posted to the UI thread.
  - `src/login.rs`: login-form script (injected into every frame at `on_load_start`, regardless of ad block state; it never signals on focus, only when `mini_request_login_fill` runs its request; it also reports visible password-field presence as `<token>:form:<frame_id>:<0|1>`, rechecked at most every 700 ms from a MutationObserver plus DOMContentLoaded/load, which Rust aggregates per tab in `TabState.login_form_frames` into `login_form_presence_changed` and resets on main-frame load start), the console signal `<token>:login:<frame_id>` (128-bit per-process token from `/dev/urandom`, sent through a `console.debug` captured at injection, consumed in `on_console_message` so it never reaches devtools), `mini_request_login_fill` and `mini_fill_login` scripts (values as escaped JSON literals, native `HTMLInputElement` value setter, `input` + `change` events, never submits). Page-side state lives on `window[Symbol.for('mini-login-' + token)]`.
  - `src/webauthn.rs`: WebAuthn suppression script injected first at every frame's `on_load_start`: `CredentialsContainer.prototype.get/create` reject with `NotAllowedError` when the options contain `publicKey` (everything else goes to the original), `PublicKeyCredential.isUserVerifyingPlatformAuthenticatorAvailable` / `isConditionalMediationAvailable` resolve false, `getClientCapabilities` resolves `{}`; overrides are non-enumerable with a native-looking `toString`. Mini has no passkey entitlement, so this keeps Chromium's hybrid (QR / phone) dialog from ever appearing. No Chromium feature switch was used: the 156 framework exposes no clearly named hybrid/caBLE disable feature.
  - `src/notifications.rs`: Web Notifications shim injected at every frame's `on_load_start` right after the WebAuthn script (same `toString`-safe, non-enumerable style). It replaces `window.Notification` (an `EventTarget` subclass with `permission`, `requestPermission` promise plus legacy callback, `onclick/onclose/onshow/onerror`, `close()`) and `ServiceWorkerRegistration.prototype.showNotification/getNotifications`, and talks over the login token's console channel as `<token>:notify-<show|close|permission>:<frame_id>:<json>` (routed from `login::handle_signal`). `requestPermission` needs user activation while the state is `default`, resolves immediately once granted or denied, and keeps one request in flight; it goes through `permissions::request_notifications` (a `PendingCallback::Notifications` entry), so the shell's normal permission card and permissions.json answer it and the page's promise resolves via `mini_permission_respond` (dismissal resolves `default`). Per-origin state comes from the shell through `mini_set_notification_permission` and is inlined into the shim at injection; `notification_show` fires only while the frame's browser-side origin is granted. `mini_notification_clicked` runs the page's click handler in the frame.
  - `src/media.rs`: media script injected at every frame's `on_load_start`; capture listeners for play/pause/ended/volumechange/emptied report (debounced 250 ms, only on change) whether any `video`/`audio` element is audibly playing plus `navigator.mediaSession.metadata` title/artist as `<token>:media:<frame_id>:<json>`; Rust aggregates per tab (`TabState.playing_frames`, reset on main-frame load start) into `audio_state_changed`. `mini_browser_control_media` pauses audible elements in every frame or resumes the ones it paused; `mini_browser_set_muted` is `host.set_audio_muted`. CefAudioHandler was not used: once `get_audio_parameters` returns true CEF captures the stream instead of playing it, so it cannot serve as a mere playing flag. WebAudio-only sounds are not detected.
  - `src/resource_requests.rs`: `MiniResourceRequestHandler` (IO thread), `on_before_resource_load` returns `CANCEL` for ad block matches.
  - `src/ad_blocking/`: Brave `adblock` engine. `mod.rs` shared state (engine `RwLock<Option<Arc<Engine>>>`, enabled `AtomicBool`, exempt hosts) and the background loader thread; `lists.rs` list URLs, 7-day refresh, download (ureq + rustls), build, `engine.dat` (de)serialization; `resources.rs` scriptlet/redirect resources; `matching.rs` CEF resource type mapping, network decision, cosmetic script. `MINI_ADBLOCK_LOG=1` logs loads and every cancelled request to stderr.
  - `src/context_menu.rs`: `MiniContextMenuHandler::run_context_menu` copies the params (link, image source when the media type is an image, selection, editable, misspelled word, up to 5 dictionary suggestions, edit-state bits mapped to `MiniEditCapability`, view coordinates) into `MiniContextMenu`, calls `context_menu_requested`, then always cancels CEF's callback. Every item is performed through ordinary ABI calls afterwards: `mini_browser_edit` (focused frame undo/redo/cut/copy/paste/del/select_all), `mini_browser_replace_misspelling`, `mini_browser_add_word_to_dictionary`, `mini_browser_inspect_element` (devtools at a point), `mini_browser_copy_image` (`download_image` in the tab's context, PNG at scale 1 through `image_copied`) and `mini_browser_save_url` (`start_download` with the chosen path parked in `CoreState.pending_save_paths`, matched by item url or original url in `on_before_download`).
  - `src/site_data.rs`: `mini_browser_clear_site_data` (View > Clear Data for This Site..., confirmed by a native sheet, main-window selected http(s) tab only): registers a `DevToolsMessageObserver` (its `Registration` lives in `TabState.site_data_observer` until the next clear or the tab closes), sends `Storage.clearDataForOrigin` with `storageTypes: "all"` through `execute_dev_tools_method`, and on that message's result deletes the origin host's cookies through the browser's own request context's `CookieManager` (so only the tab's space is touched), then reloads from the `DeleteCookiesCallback`. Verified: a page's cookie and localStorage both read empty after the reload.
  - `src/navigation.rs`: session history visitor and `history.go` offsets (see NavigationHistory.swift).
  - `src/downloads.rs`: `~/Downloads/<name>` destination with `name (1).ext` uniquifying (unit tested). The download handler reports every `on_download_updated` through `download_updated` (interrupted counts as canceled) and keeps the latest `DownloadItemCallback` per id in `CoreState.download_callbacks` for `mini_download_cancel`.

## Verified external facts

- `cef` crate 156.2.0+156.0.14. `cef-dll-sys` downloads CEF into `$CEF_PATH/<version>/` (Makefile sets `CEF_PATH=$HOME/.local/share/cef`) and builds `libcef_dll_wrapper` with cmake + Ninja (both from Homebrew).
- `LibraryLoader::new(exe, helper)` resolves the framework at `../Frameworks/` (main) or `../../..` (helper) relative to the executable; `cef::sandbox::Sandbox` loads `libcef_sandbox.dylib` from the framework and must init first in helpers.
- Call `cef::api_hash(sys::CEF_API_VERSION_LAST, 0)` after loading the library and before any other CEF call.
- objc4 `conformsToProtocol:` matches protocols by name, so Swift `@objc(CefAppProtocol)` protocols satisfy CEF's checks.
- CEF lands at `$HOME/.local/share/cef/156.0.14/cef_macos_aarch64/` (minimal distribution); the framework is `Chromium Embedded Framework.framework` in that dir. `bundle.sh` derives `156.0.14` from the `cef-dll-sys` version in `core/Cargo.lock`. The wrapper build lands under `core/target/<profile>/build/cef-dll-sys-*/out/`.
- `cargo rustc --release -p mini-core -- --print native-static-libs` prints `-lc -lm -liconv -framework AppKit -framework Foundation -framework CoreFoundation -lobjc -lSystem` (`-liconv` arrived with the ad block dependencies). The Swift link also needs `-lc++` (libcef_dll_wrapper is C++) and dead stripping (`-Wl,-dead_strip`, SwiftPM's default): the `cef` crate always compiles wrappers for `cef_sandbox_initialize`/`cef_sandbox_destroy`, which only exist in `libcef_sandbox.dylib`, so a link without dead stripping fails on those two symbols. Verified by linking an ObjC test app.
- Threads: CEF calls `auth_credentials`, `resource_request_handler` and `on_before_resource_load` on the IO thread; everything else Mini implements runs on the UI (main) thread. Swift callbacks are only ever invoked from UI-thread code; the `thread_local` core state panics if touched elsewhere.
- `adblock` 0.13.3: the default `single-thread` feature makes `Engine` neither `Send` nor `Sync`; Mini uses `default-features = false` + `embedded-domain-resolver`, `full-regex-handling`. `Engine::serialize` stores filters only, not resources, so resources are re-attached (`use_resources`) after every `deserialize`. A serialized engine is ~8.5 MB; the full lists are ~6.5 MB.
- uBO's scriptlets are now ES modules (`src/js/resources/scriptlets.js` + imports) that adblock's resource assembler cannot parse (its scriptlet parser is deprecated, old format only). Mini instead downloads Ghostery's uBO-derived bundle `https://raw.githubusercontent.com/ghostery/adblocker/master/packages/adblocker/assets/ublock-origin/resources.json` (`{scriptlets:[{name,aliases,body,dependencies,executionWorld?,requiresTrust?}], redirects:[{name,aliases,contentType,body}]}`) and converts it: `*.fn` names become `fn/javascript`, `requiresTrust` scriptlets need permission bit 1 (granted only to the uBO lists), `executionWorld: ISOLATED` scriptlets are dropped (execute_java_script runs in the main world), `;base64` content types keep their body as-is.
- Filter list URLs: `https://easylist.to/easylist/easylist.txt`, `https://easylist.to/easylist/easyprivacy.txt`, `https://ublockorigin.github.io/uAssets/filters/{filters,badware,privacy,quick-fixes,unbreak}.min.txt` (the `.min` builds have no `!#include`), `https://pgl.yoyo.org/adservers/serverlist.php?hostformat=adblockplus&showintro=1&mimetype=plaintext`.
- `$redirect` matches are cancelled, not redirected (CEF cannot serve the redirect body from `on_before_resource_load` without a resource handler).
- cef-rs trap: `CefStringList::clone()` of a callback-provided list yields an empty list (the clone becomes `Borrowed`, whose `into_iter` reads nothing). Iterate with `std::mem::take(list).into_iter()`.
- `execute_java_script` from `on_load_start` runs in the new document (verified: the login script's window symbol is present after load), so load-start injection works for cosmetic CSS and the login detector.
- `Browser::load_url("javascript:...")` executes in the current page (used only by the scratchpad harness).
- `download_image` handles SVG favicons (GitHub's) and `.ico`; `Image::as_png` needs non-null width/height out params.
- - `do_close` must not return 0 for a browser embedded in the shell's window: CEF then calls `performClose:` on the host NSWindow and the browser never reaches `on_before_close`. Mini removes the browser NSView from its superview and returns 1, which destroys just that browser.
- Ad-hoc signing traps cookie encryption: Chromium reads the "Chromium Safe Storage" login-keychain item at startup, and its ACL trusts each ad-hoc build by cdhash. Any code change gives a new cdhash, so the next launch raises a SecurityAgent "Always Allow" prompt; until it is answered the cookie store never loads and every navigation stalls before reaching the network (blank page, stop button, no load_start). bundle.sh therefore signs with a stable certificate identity by default, whose keychain grant survives rebuilds. With ad-hoc signing, answer the prompt. `--use-mock-keychain` confirms the diagnosis but re-encrypts cookies with a fixed key, so never run it against the real profile. Identical sources rebuild to the same cdhash.
- Every build signed with a certificate uses the hardened runtime (`--options runtime`) so local and released builds behave the same; ad-hoc builds skip it because library validation would reject the separately signed framework without a Team ID. Local builds sign with `--timestamp=none` (no network round trip per binary); `MINI_TIMESTAMP=1` adds the secure timestamp notarization needs. The hardened runtime does not change the designated requirement (identifier + Developer ID leaf, OU 5W853CJW28), so the Chromium Safe Storage keychain grant survives. Verified under the hardened runtime: pages load, VP9 video plays (GPU process), the camera permission card appears, weather re-fetches location. CEF ships without proprietary codecs, so H.264 MP4 does not play (unrelated to signing).
- Two browser processes sharing one `root_cache_path` collide (`bootstrap_check_in ... Permission denied`) and the second hangs in `cef_shutdown` until "Teardown watchdog expired". Kill stale instances before relaunching.
- `video.requestPictureInPicture()` works in CEF 156 Alloy (verified on a VP9 WebM: the promise resolves and Chromium opens its own 428x241 PiP window). It needs user activation; script run through `Browser::load_url("javascript:...")` has it, `execute_java_script` does not, so View > Picture in Picture (Opt-Cmd-P) sends a `javascript:void(...)` URL that toggles the largest playing video (main frame plus same-origin iframes) or exits PiP.
- With no JS dialog or file dialog handler, CEF 156 Alloy's defaults work: `alert`/`confirm`/`prompt` show app-modal `_NSAlertPanel`s (titled "JavaScript Alert - <origin>", prompt has a text field) and return the user's answer to the page; `<input type=file>` opens an `NSOpenPanel` sheet on the main window. Verified with a scratch page; Mini adds no handler for them.
- Spell checking works in Alloy with the macOS checker, but Chromium only marks words after an edit in the field (focus alone leaves the text unchecked); right-clicking a marked word then reports `misspelled_word` and suggestions, and `replace_misspelling` replaced it (verified).
- Synthesized `rightMouseDown`/`rightMouseUp` NSEvents sent with `NSApp.sendEvent` at a point over the CEF view reach Chromium and produce `run_context_menu`, which is how the debug harness drives context menus without System Events.
- Page fullscreen in CEF 156 Alloy windowed mode only resizes the web contents to the browser view; the embedder makes the view fill the screen. Verified with a VP9 `<video>` (`requestFullscreen` through a `javascript:` URL for user activation) and YouTube's fullscreen button: the webAreaView fills the 1920x1205 fullscreen window, `document.fullscreenElement` is set, and exit restores the sidebar, toolbar and window size.
- `BrowserHost::print` (File > Print..., Cmd-P, `mini_browser_print`) opens Chromium's native NSPrintPanel as an app-modal panel (`NSApp.modalWindow`, not a sheet); `NSApp.abortModal()` cancels it like the Cancel button. While it is up only common-mode run loop sources fire, so `DispatchQueue.main.asyncAfter` steps wait until it closes.
- `chrome://crash` loaded with `load_url` crashes the renderer and fires `on_render_process_terminated` (used to test the crash overlay).
- After a download is canceled CEF may report an empty `full_path` and file name; the shell keeps the last non-empty values.
- Renderer-initiated `window.open` to a `data:` URL is blocked by Chromium even after `on_before_popup` allows it; test popups with real URLs.
- Swift 6: the CrApp/CefApp protocols are declared `@MainActor @objc(Name)` so the main-actor NSApplication subclass can conform. C callbacks convert strings to `String` before `MainActor.assumeIsolated`, and pass pointers across it as `UInt` bit patterns (raw pointers are not Sendable).
- Every `mini_browser_*` call for a tab whose browser does not exist (lazy tab, or after `browser_closed`) panics in Rust. The shell gates on `Tab.browserState == .created`; a popup tab is `.pendingPopup` until the `popup_requested` callback has returned (promoted on the next main-queue turn).
- Tab ids are never reused: once `browser_closed` fires for an id, Rust rejects further calls, so a reset pinned tab gets a new Tab object and id.
- Hidden menu items need `allowsKeyEquivalentWhenHidden = true` to keep their shortcut (used for Cmd-+ and Opt-Cmd-Up/Down).
- The sidebar NSHostingView must have `sizingOptions = []`, or SwiftUI's fitting size fights the split view and the sidebar renders offset and clipped.
- `webAreaView` is positioned by explicit constraints, never by NSBackgroundExtensionView's automatic placement: top = `window.contentLayoutGuide` top (below titlebar and toolbar), leading = the content view's `safeAreaLayoutGuide` (sidebar overlap). Automatic placement let the CEF view slide under the toolbar and hide the traffic lights, and did not follow sidebar toggles.
- NSBackgroundExtensionView's internal `_NSCoreHostingView<BackgroundExtensionContainer>` sits above its content view and swallows every click; `PassthroughBackgroundExtensionView` overrides `hitTest` to route into the content view.
- An NSHostingView whose content can be empty (command bar suggestions) must drop `.maxSize` from `sizingOptions`, or its required max-width constraint collapses fixed-width containers.
- Overlays live in the content item's view (`rootView`), never in the NSSplitView itself (its subviews are panes).
- In an inactive window AppKit delivers the activating click only to views whose `acceptsFirstMouse` returns true (CEF's browser views do); the split divider overrides it so it drags on the first click.
- AeroSpace (the tiling window manager on this Mac) tiles every new standard window, so a little window shows at 960x680 only until AeroSpace resizes it; its own frame code is correct (logged 960x681 before tiling).
- A `CATransition` added to `webAreaView`'s layer leaves CEF browser views blank when they are unhidden in the same transaction (tab switch back to an existing browser showed an empty web area). Animate `alphaValue` instead.
- Popups get their opener's request context from CEF (`on_before_popup` does not set one), so popups stay in the opener's space.
- zsh here has `noclobber`: overwrite files with `>|` or an editor, not `>`.
- `swift build` in this toolchain uses the swiftbuild backend: products live in `shell/.build/out/Products/<Config>/`, so `bundle.sh` asks `swift build --show-bin-path` instead of assuming `.build/<config>/`.
